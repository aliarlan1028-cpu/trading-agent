# Kordyn 交互式交易操作系统原型设计规格

- 日期：2026-08-21
- 状态：已完成对话设计确认，等待书面规格复核
- 交付物：`prototypes/kordyn-operating-system.html`
- 原型类型：单文件、无后端、桌面优先、响应式交互原型

## 1. 目标

建立一个可直接在浏览器打开的 Kordyn 全功能交互原型，用于验证新的产品信息架构、界面布局、视觉语言与核心业务流程。

本次重构保留现有系统功能，但不保留旧页面边界、卡片式仪表盘和菜单组织。系统改为以任务和业务对象为中心的交易操作环境：用户从待处理事项进入市场、计划、持仓、知识、策略、Agent Run 或审计对象，并在共享的上下文与事实链中完成工作。

原型成功标准：

1. 现有功能均有明确入口和新归属。
2. AI、情报、观察、交易、风险、复盘、知识、优化和审计形成可点击演示的闭环。
3. 视觉不仅改变颜色，还重构信息层级、空间关系和交互方式。
4. 原型无需安装依赖，可离线打开；外部字体不可用时使用系统字体回退。
5. 所有模拟操作均明确标记为演示，不产生真实交易或配置变更。

## 2. 设计方向

### 2.1 产品架构

采用“任务空间 + 对象工作台”架构，并以七阶段交易生命周期作为共享事实链。

一级任务空间：

1. Command：情报、观察、候选信号、AI 决策和待授权事项。
2. Live Desk：市场、账户、持仓、计划、执行、订单、成交和保护单。
3. Lab：知识、策略、验证、交易复盘、Owner 优化、能力与工具。
4. Control：风险态势、Mandate、风险预算、规则和风险事件。
5. Run Control：Agent、任务、连接、事件、通知、系统健康和审计。
6. Administration：环境、网络、备份、安全、OKX、模型、密钥、用户和订阅。

共享生命周期：

`Sense → Recall → Plan → Guard → Execute → Monitor → Review`

### 2.2 视觉语言

视觉参考 `https://e2pdao.xyz/club/` 的 `ILLUSTRATIVE PRODUCT VIEW` 与 `03 / Research & operations`，吸收其编辑式版式与操作系统感，不复制 E2P 品牌、标志、文案或页面结构。

基础视觉令牌：

| 语义 | 值 | 用途 |
| --- | --- | --- |
| Paper | `#F4F1E9` | 主背景 |
| Ink | `#111311` | 主文字、硬边界 |
| Dark Panel | `#111511` | AI 计划、执行、风险和关键决策 |
| Acid | `#CCFF3D` | 当前阶段、待行动、Guard、主要操作 |
| Mint | `#4FB78B` | 健康、来源、证据与完成状态 |
| Danger | `#E25645` | 阻断、失败和破坏性操作 |
| Line | `rgba(17,19,17,.16)` | 网格和分隔线 |

字体层级：

- 编辑式标题：Manrope 风格，系统回退为 Arial/Helvetica。
- 正文与操作：DM Sans 风格，系统回退为 Arial/Helvetica。
- 状态、编号、时间、ID 和指标：Space Mono 风格，系统回退为 Menlo/Consolas。

形态原则：

- 以连续网格、1px 硬边界和矩形面板组织内容。
- 不使用普通 SaaS 卡片墙、大圆角、装饰渐变和普遍阴影。
- 酸性绿仅用于当前状态、待处理操作和风险 Guard。
- 黑色反差面板只用于重要决策、执行、风险和系统流程。
- 页面标题具有编辑式留白，但操作页控制在 42–52px，避免营销页尺度干扰工作。
- 状态同时使用文字、图标和颜色，不依赖颜色单独传达含义。

## 3. 全局应用骨架

### 3.1 Command Rail

顶部固定轨道提供：

- Kordyn 标识与当前租户。
- 全局对象搜索与快捷命令入口。
- OKX 连接状态。
- 数据新鲜度和延迟。
- Demo / Live 模式。
- 观察哨运行数和待复核数。
- 通知入口。
- Flatten All 与 Kill Switch。

Flatten All 和 Kill Switch 始终可达，但必须先打开影响范围确认层。原型只演示确认过程。

### 3.2 Workspace Rail

左侧任务空间轨道使用编号、图标、名称和一句职责说明。当前空间使用近黑背景和酸性绿标记。

### 3.3 Context Dock

右侧共享检查器按当前对象切换以下内容：

- Evidence：来源、覆盖率、可信等级和数据新鲜度。
- Risk：风控预检、规则命中和风险预算。
- Mandate：权限范围、期限、市场和杠杆边界。
- Object：当前计划、持仓、知识、策略或 Run 的属性。
- Version：版本历史与差异。
- Permissions：角色、影响范围和允许操作。

Context Dock 可以收起，不能在每个工作空间复制另一套相同卡片。

### 3.4 Trace Rail

底部共享事实链显示七个阶段及其完成、等待、阻断状态。点击阶段展开对应事实、工具调用、授权、订单事件或复盘内容。

### 3.5 Object Switcher

全局搜索模拟查找并跳转以下对象：

- 市场
- 情报事件
- 观察任务
- 交易计划
- 持仓
- 订单与成交
- 交易复盘
- 知识
- 策略与验证 Run
- Agent Run
- 审计记录
- 功能入口

## 4. Command

Command 回答“现在发生了什么、系统正在等待什么、需要用户决定什么”。

### 4.1 工作队列

队列支持三个视图，不维护三套对象：

- Feed：新闻快讯、宏观事件、资金费率、持仓量、基差、链上与市场结构变化。
- Watch：正在运行、等待确认、暂停、过期的观察任务。
- Decide：AI 待复核计划、风险警告和待授权操作。

每个队列项显示对象类型、市场、状态、来源、更新时间、数据新鲜度和下一步动作。

### 4.2 Decision Dossier

中央工作区打开当前对象：

- AI 结论与不确定性。
- 事实、推断、建议和待确认操作分层。
- 黑色结构化计划面板。
- 入场、失效、止损、目标、规模、杠杆和风险预算。
- 情景路径和取消条件。
- Evidence、Hard Risk 和 Human Approval 状态。

### 4.3 情报与观察交互

支持：

- 将情报加入决策证据。
- 从情报创建观察条件。
- 暂停、恢复、修改或终止观察任务。
- 查看条件接近度和下一次检查时间。
- 要求 AI 立即复核。
- 将复核结果转为 Watching、Rejected 或 Qualified。
- Qualified 对象生成结构化交易计划。

### 4.4 Command Bar

AI 对话作为底部任务输入条，而非整个页面。提供快捷问题、模拟回复和当前市场上下文。

## 5. Live Desk

Live Desk 合并市场、账户、持仓、执行、订单、成交和保护状态，避免在多个相似页面之间跳转。

### 5.1 Market Canvas

- 市场与时间框架选择。
- 模拟价格图、成交量、入场区域、止损和目标线。
- 市场状态、资金费率、OI、基差和数据新鲜度。
- 选择持仓或计划时更新图表标注。

### 5.2 Plan Ladder

右侧执行面板按顺序展示：

1. 计划状态。
2. 方向、价格类型与条件。
3. 仓位规模和保证金。
4. 止损、止盈与保护覆盖。
5. Risk Preflight。
6. 授权范围与确认操作。

计划、订单和持仓是不同对象；停止 Agent、取消计划、取消订单和平仓必须使用不同词义和操作。

### 5.3 Exposure Rail 与 Ledger

账户暴露固定显示总权益、可用保证金、净 Delta、风险使用率和保护覆盖率。

底部 Ledger 提供：

- Positions
- Orders
- Fills
- Protection
- Trace

选择行后以内联详情或底部抽屉展开，不跳转到重复页面。

## 6. Lab

Lab 将知识、策略、验证、交易复盘、Owner 优化和能力工具组织为研究对象系统。

本地模式：`Library | Strategies | Validations | Learn | Capabilities`

### 6.1 Library

左侧为知识 Registry，右侧为 Provenance Inspector。

知识对象类型：

- 交易复盘知识
- 市场结构事实
- 策略规则
- 风险经验
- 外部研究
- 用户导入文档
- AI 生成的未审核候选

详情显示结论、来源、可信度、版本、新鲜度、市场标签、引用它的决策、相关交易和生命周期。

支持导入研究、查看来源、标记验证或过期、创建版本、关联对象、归档和提升知识候选。

### 6.2 Strategies

策略拆为三个对象：

- Strategy Spec：逻辑、参数、适用市场和版本。
- Validation Run：回测、前向、压力和稳定性验证。
- Release：Demo / Live 资格、批准和回滚记录。

策略 Registry 使用状态、市场、版本、证据覆盖和最后运行筛选。选择策略后更新右侧版本与验证详情。

### 6.3 Validations

展示收益、回撤、Sharpe、Profit Factor、样本量、置信下界、市场状态拆分、参数稳定性和模拟/实盘差异。Run 可在列表中对比，但原型不执行真实回测。

### 6.4 Learn

Learn 统一承载交易复盘和 Owner 优化候选。

交易复盘使用 Review Dossier，沿 `Plan → Approval → Risk → Orders → Position → Exit` 展示计划与实际事实。指标包括盈亏、ROI、费用、资金费率、MAE/MFE、滑点、保护覆盖和退出原因。

复盘支持标记人为、模型、执行或市场偏差，并生成 Knowledge Candidate、Optimization Candidate 或“无需学习”。

Owner 优化候选生命周期：

`Candidate → Reviewing → Backtesting → Forward Validation → Approved → Released → Monitoring → Rolled Back`

优化对象包括策略参数、风险建议、Agent 行为、模型路由、工具选择、机会过滤、退出逻辑和数据源权重。发布前必须查看样本、版本差异、验证与风险影响。

### 6.5 Capabilities

能力与工具 Registry 显示工具/Skill 名称、作用域、权限、健康、最后使用、调用次数、沙箱状态和关联 Agent。选择后展示输入输出边界和最近 Run。

## 7. Control

Control 分离实时风险状态和策略配置。

### 7.1 Control Room

首先给出“允许交易、仅减仓、暂停自主或阻断”的明确结论，并展示：

- 剩余日/周/月亏损预算。
- 杠杆、保证金、相关性与集中度。
- 保护覆盖率。
- 即将到期的 Mandate。
- 当前影响交易的规则。
- 需要处理的风险事件。

### 7.2 Mandates

以范围矩阵展示允许市场、账户、方向、杠杆、单笔风险、总风险、期限和批准人。支持模拟编辑、续期、暂停和撤销。

### 7.3 Policy Studio

用于市场白名单、仓位和杠杆、损失预算、动态风险规则、事件窗口与只读降级条件。规则编辑与紧急操作不能出现在同一表单。

### 7.4 Incidents 与紧急操作

风险事件使用时间线展示触发、影响、处置和解除条件。

暂停自主、只减仓、Flatten All 与 Kill Switch 使用四种不同语义。确认层必须说明影响对象、会做什么、不会做什么和模拟结果。

## 8. Run Control

Run Control 以系统数据流为顶部结构：

`Market Data → Agent → Risk Engine → Execution → Audit`

### 8.1 系统与 Agent

- 顶部显示数据延迟、交易所同步、风险引擎、Agent Queue、通知和审计健康。
- 左侧对象树包含 Agent、任务、连接和服务。
- 中央显示所选 Run 的步骤、状态和耗时。
- 右侧显示输入摘要、输出、工具调用、错误、重试和版本。

### 8.2 统一事件流

事件、通知和审计共享一条数据流，但使用不同过滤层：

- Event Stream：系统实时事件。
- Notifications：需要送达用户的事件投影。
- Audit：正式、不可变的动作记录。

支持状态筛选、选择 Run、模拟 Replay 和切换一次数据过期/降级状态。

## 9. Administration

Administration 先按作用域选择：`System | Tenant | Trading Account | User`，再编辑配置。

配置域：

- 环境与服务
- 网络代理
- 数据与备份
- 登录与凭证安全
- OKX 连接与权限
- 通知渠道
- 模型、密钥与路由
- Agent 配置
- 用户、角色和权限
- 订阅、额度和到期状态

API Key、模型密钥、Owner 权限和 Live 环境进入独立 Secure Session。普通设置使用内联编辑和范围明确的保存反馈。

## 10. 角色与权限

原型支持 Owner / Trader 角色切换。

- Owner 可以访问优化发布、用户、订阅、密钥和系统级配置。
- Trader 保留交易、研究、复盘和授权范围内的操作。
- 无权限入口保持可见并显示锁、权限原因和获取条件，不泄露受限数据。

## 11. 交互状态模型

单文件 JavaScript 维护以下模拟状态：

- 当前任务空间和本地模式。
- 当前市场与时间框架。
- 当前队列对象、计划、知识、策略、Agent 和 Run。
- Context Dock 当前标签与开合状态。
- Trace Rail 当前阶段与详情。
- 观察任务状态和条件接近度。
- 计划审批状态。
- 风险模式与模拟降级状态。
- Owner / Trader 角色。
- 抽屉、确认层、通知和演示 Toast。

数据集中定义为静态对象，渲染函数按业务对象更新相关区域，避免在点击处理器中散落重复 HTML。

## 12. 响应式

桌面 1440×900 为主要验收视口。

- 宽屏：Workspace Rail + Workbench + Context Dock，Trace Rail 固定在底部。
- 中屏：Context Dock 变为可打开侧层。
- 窄屏：一级任务空间使用底部导航，Context Dock 和 Trace 使用全屏详情层；表格转换为可排序行列表。
- 移动端不删除字段、状态、确认步骤或审计反馈。

## 13. 错误、空状态与安全状态

- 数据过期显示全局降级条，并影响计划资格和 Risk Preflight。
- 连接断开、风险阻断、无权限和空数据使用独立状态，不显示成普通空白页。
- 危险操作完成后显示结果对象和审计 ID，而非仅显示 Toast。
- 所有原型动作标明 `DEMO / NO LIVE ACTION`。

## 14. 验证

实施后需要完成：

1. 直接打开 HTML，无控制台致命错误。
2. 六个任务空间和全部本地模式可访问。
3. 情报 → 观察 → AI 复核 → 计划 → 风控 → 授权可点击演示。
4. 持仓、订单、成交、保护和 Trace 能联动当前市场对象。
5. 复盘能生成知识或优化候选并跳转到 Lab 对象。
6. Owner / Trader 切换产生正确的权限差异。
7. 数据过期模拟触发全局降级和执行阻断。
8. Flatten All 与 Kill Switch 显示不同的影响说明和模拟结果。
9. 1440×900 与 390×844 视口无关键内容丢失或不可操作。
10. 所有按钮要么执行可见交互，要么明确标为未来能力，不保留无反馈的死控件。

## 15. 非目标

- 不连接真实后端、交易所、模型或账户。
- 不改变现有 React 应用、API 或业务状态机。
- 不使用真实账户数据或承诺交易表现。
- 不实现真实回测、订单执行、配置保存或认证。
- 不复制参考网站的品牌资产、Logo 或营销内容。
