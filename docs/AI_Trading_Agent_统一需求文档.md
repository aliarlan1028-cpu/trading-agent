# AI 数字货币交易 Agent 统一需求文档

版本：v1.0  
日期：2026-07-01  
整合来源：`AI数字货币交易Agent_PRD_v1.1_自主交易与Agent底座增强版.docx`、`专家知识库与金融书籍智能体_需求文档_v1.0.docx`、概念图

## 1. 产品定位

AI 数字货币交易 Agent 是一个面向 OKX、Binance 等交易所的专属自主交易系统。系统以 AI 交易员为任务执行核心，以专家知识库为长期专业大脑，以授权委托和硬风控作为交易边界，以定时任务、事件跟进、Skill/Tool/MCP 扩展和审计追踪作为 Agent 运行底座。

一句话定义：一个可以学习用户交易体系、持续感知市场和事件、调用工具、在授权范围内执行真实交易、管理仓位、复盘改进，并被权限、风控和审计约束的数字货币交易驾驶舱。

## 2. 核心原则

1. 授权后自主交易，但绝不无边界交易。
2. 真实交易必须经过结构化交易计划、授权范围校验、风控引擎和执行器。
3. 禁止提现权限，API Secret 不进入模型上下文、前端和普通日志。
4. 外部网页、书籍、GitHub、Skill、MCP 只能作为资料或工具，不能绕过风控直接下单。
5. 专家知识库不是资料仓库，而是将书籍、研报、复盘和链接转化为概念、框架、规则、反方观点和证据链。
6. 每笔交易、任务、事件更新、Skill 调用、风控拦截和权限变更必须可追踪、可解释、可审计。

## 3. 目标用户与核心场景

目标用户包括个人量化/半量化交易者、数字货币交易员、多交易所用户、需要专属交易 Agent 的高级用户，以及希望将金融书籍和交易知识沉淀为长期能力的用户。

核心场景：

1. 自主交易授权：用户设置交易所、账户、币种、策略族、最大风险、杠杆上限、有效期和人工确认阈值，Agent 在授权范围内自主下单、撤单、改单、移动止损、分批止盈和平仓。
2. 实时事件跟进：Agent 跟踪 CPI、FOMC、ETF 审批、交易所维护、链上异常、项目解锁、安全事件等，并将事件影响传递给交易和风控。
3. 定时任务自动化：支持 Cron、At、Every、事件相对时间任务，用于行情扫描、仓位对账、事件刷新、知识库更新和日终复盘。
4. 专家知识运行时调用：在交易计划生成、事件分析、风控审查和复盘中自动召回宏观、衍生品、市场微观结构、Crypto、风险和个人经验知识。
5. Skill/Tool/MCP 扩展：从 GitHub、ClawHub、私有仓库、上传包或 MCP Server 导入工具，经过扫描、沙箱、权限声明、版本 pin 和审计后启用。
6. 复盘进化：交易结束后生成复盘，记录入场理由、执行偏差、盈亏归因、错误标签，并提出知识库或风控规则更新建议。

## 4. 系统模块

### 4.1 Agent Runtime

必须支持多轮记忆、Tool Calling、ReAct 循环、有状态 Agent、状态文件、受控命令执行、模块化工具层、Tracing Web UI、三层记忆、LangSmith 链接、MCP 协议和 Skill 系统。

Agent 角色包括：

1. AI 交易员：生成交易假设和结构化交易计划。
2. 风控官：执行授权、风险、事件、执行和 Skill 级检查。
3. 执行员：将通过风控的计划转成交易所订单。
4. 事件分析员：发现、建档、更新事件进度。
5. 调度员：管理 Cron、At、Every 和事件相对任务。
6. 研究员：导入资料、解析链接、蒸馏知识。
7. Memory Agent：维护工作记忆、情景记忆和语义记忆。
8. Skill Manager：导入、扫描、安装、更新和回滚 Skill/Tool。
9. 复盘员：完成交易和事件复盘。

### 4.2 自主交易授权 Mandate

Mandate 是 Agent 的交易许可证，字段包括授权账户、交易所、市场类型、允许/禁止币种、策略范围、单笔风险、日亏损、周回撤、杠杆、名义仓位、有效期、人工确认阈值、允许动作和熔断条件。

状态机：

只读观察 -> 等待授权 -> 授权生效 -> 自主交易运行中 -> 风控冷却 / 熔断停机 / 授权过期 / 只读观察

任何状态下，用户可手动停止并回到只读观察。

### 4.3 交易生命周期

1. 市场与事件感知。
2. 专家知识库生成 analysis_bundle_id。
3. AI 交易员生成结构化交易计划。
4. MandateGuard 校验授权范围。
5. RiskEngine 校验单笔风险、日亏损、杠杆、止损、滑点、事件风险和执行风险。
6. Executor 通过统一交易所适配器执行。
7. PositionMonitor 监控成交、止损、止盈、资金费率和失效条件。
8. Scheduler、Event、Risk 可触发减仓、撤单、暂停或熔断。
9. ReviewAgent 复盘并写回记忆和知识库候选规则。

### 4.4 交易所接入

核心交易所为 Binance 与 OKX。系统通过统一 `ExchangeConnector` 屏蔽签名、账户模式、订单类型和错误码差异。接口包括行情、盘口、余额、持仓、挂单、下单、改单、撤单、平仓、设置杠杆、资金费率、成交和账户对账。

生产要求：

1. Read 权限必须，Trade 权限仅在授权后启用，Withdraw 权限禁止。
2. 下单必须使用 clientOrderId 或幂等键。
3. REST 与 WebSocket 双通道对账。
4. 止损挂单失败必须进入高危状态。
5. API 异常、限速、签名失败、对账差异必须进入异常看板并可触发熔断。

### 4.5 风控与安全

风控分为账户级、交易级、执行级、事件级和 Skill 级。风控动作包括提醒、限制、禁止新仓、减仓、撤单、熔断和只读降级。

高优先级硬规则：

1. 授权过期、币种不在白名单、市场类型不在范围内时拒绝交易。
2. 无止损、超杠杆、超单笔风险、超日亏损、超周回撤时拒绝交易。
3. 高影响事件或 API 对账异常时禁止新开仓，仅允许降低风险动作。
4. 第三方 Skill 不得直接调用交易所交易接口。
5. API Secret 不得进入前端、LLM 上下文或普通日志。

### 4.6 事件跟进

事件类型包括宏观、监管、交易所、项目、安全、链上和市场结构事件。事件生命周期为：

发现 -> 去重 -> 建档 -> 可信度评分 -> 影响评估 -> 进度跟踪 -> 交易影响决策 -> 定时复查 -> 事件关闭 -> 事件复盘 -> 写入记忆/知识库

事件卡必须记录标题、摘要、来源、可信度、影响分、进度状态、下一节点、关联资产、影响方向、Agent 建议动作、触发任务和复盘结果。

### 4.7 定时任务

任务类型包括 Cron、At、Every 和 Event-relative。任务对象包含类型、调度表达式、执行 Agent、工具 allowlist、最大运行时间、重试策略、并发锁、启用状态和运行日志。

P0 任务模板：

1. 行情扫描。
2. 仓位与订单对账。
3. 资金费率和 OI 检查。
4. 重要事件进度刷新。
5. 知识库订阅源刷新。
6. 日终复盘。

### 4.8 专家知识库

专家知识库将书籍、论文、研报、网页、GitHub、RSS、个人笔记和复盘转化为可调用知识。

知识产物包括：

1. 来源记录与权限元数据。
2. 文档结构树、章节、表格、公式、图表说明。
3. 书籍卡、章节卡、概念卡、理论框架卡、案例卡。
4. 冲突观点、适用条件、失效条件和反方观点。
5. 交易启发、软建议、待审批硬规则。
6. 专家图谱和运行时证据包。

交易前要求：每个自主交易计划必须调用专家知识库并生成 `analysis_bundle_id`。若知识库不可用，系统按风险配置降级为保守模式或禁止交易。

### 4.9 Skill、Tool 与 MCP

支持 GitHub、ClawHub、私有仓库、上传包和 MCP Server。安装流程：

来源提交 -> 元数据读取 -> 静态扫描 -> 依赖扫描 -> 权限解析 -> 沙箱 smoke test -> Skill Card -> 用户批准 -> 版本 pin -> 启用 -> 调用审计

第三方 Skill 默认不可信，只能在声明权限和沙箱边界内运行。

### 4.10 可观测性与审计

必须记录 LLM 调用、ReAct Step、Tool Call、交易计划、风控检查、交易执行、定时任务、Skill 安装/调用、事件更新、知识库调用和权限变更。

审计日志 append-only，支持导出 CSV/JSON。交易、授权、风控、熔断、密钥元数据和 Skill 安装日志不可被普通用户删除。

## 5. 页面与交互

概念图对应的信息架构如下：

1. 总览驾驶舱：资产、今日/本周盈亏、回撤、风险状态、授权状态、市场图表、AI 当前判断、下一步行动、持仓、重要事件、定时任务和底部状态栏。
2. 市场行情：交易对切换、K 线、资金费率、OI、成交量、关键指标。
3. 持仓与订单：持仓、入场理由、止损止盈、强平距离、AI 建议、挂单、成交与滑点。
4. AI 决策：市场判断、交易计划候选、知识调用、事件影响、禁止行为。
5. 策略与计划：策略族、交易计划 JSON、审批状态、执行状态。
6. 实时事件：事件雷达、进度流、来源、倒计时、触发任务和交易影响。
7. 定时任务：任务列表、下次运行、运行历史、失败重试、权限和日志。
8. 专家知识库：资料导入、书籍库、概念卡、理论框架、交易规则、运行时证据面板。
9. Skill Center：发现、导入、扫描、权限、安装、启用、回滚、调用审计。
10. MCP/Tool Registry：Server、工具列表、权限和健康状态。
11. 风控管理：账户级、交易级、事件级、Skill 级规则，熔断和冷却。
12. 安全审计：API Key 元数据、权限变更、风控拦截、异常告警、熔断记录。

## 6. 核心数据模型

核心集合包括：

1. 用户与权限：users、roles、permissions。
2. 交易所账户：exchange_accounts、api_key_metadata。
3. 自主授权：autonomy_mandates。
4. 市场数据：candles、orderbooks、funding_rates、open_interest。
5. 交易：trade_plans、orders、fills、positions。
6. 风控：risk_rules、risk_checks、risk_incidents。
7. 事件：event_cards、event_updates、event_sources。
8. 调度：scheduled_tasks、job_runs、job_locks。
9. 知识库：knowledge_sources、document_nodes、knowledge_chunks、book_cards、concept_cards、theory_frameworks、trading_rules、analysis_bundles。
10. Skill/Tool：skill_sources、skill_packages、tool_registry、tool_permissions。
11. MCP：mcp_servers、mcp_tools、mcp_resource_refs。
12. 可观测性：agent_runs、traces、tool_calls、audit_logs。
13. 复盘：trade_reviews、event_reviews、strategy_metrics。

## 7. API 范围

P0 API 包括：

1. Auth/User：登录、当前用户、偏好。
2. Exchange：账户绑定、余额、持仓、订单、对账。
3. Mandate：创建、更新、撤销、暂停、恢复。
4. Trade：交易计划、风控检查、订单执行、仓位管理。
5. Risk：风险状态、规则检查、一键熔断。
6. Events：事件创建、列表、更新、复盘。
7. Scheduler：任务创建、暂停、恢复、立即运行、运行日志。
8. Knowledge：导入、解析、卡片、规则审批、运行时召回。
9. Skills：导入、扫描、安装、回滚、启用、禁用。
10. MCP/Tools：Server 注册、工具列表、权限更新。
11. Observability：trace、audit log、agent run。

## 8. MVP 范围

MVP 必须包含：

1. 概念图风格总览驾驶舱。
2. Mandate 授权管理与状态机。
3. 交易计划 JSON、授权校验、风控校验和受控执行器。
4. OKX/Binance 统一连接器接口，真实写操作默认关闭。
5. 事件卡、进度流、影响评分和交易影响。
6. Cron/At/Every 任务模型、任务日志和立即运行。
7. 专家知识库导入、卡片、规则草案、运行时 analysis bundle。
8. Skill/Tool/MCP 注册、扫描、权限、启用和审计。
9. Tracing、审计日志和一键熔断。
10. 复盘记录与知识库写回建议。

## 9. 里程碑

1. M1：Agent 底座与驾驶舱。交付前端导航、总览、状态文件、基础 API、Tracing 和审计。
2. M2：授权、风控与交易闭环。交付 Mandate、交易计划、风险检查、受控执行器和持仓监控。
3. M3：事件与定时任务。交付事件跟进、任务调度、事件影响风控和任务运行日志。
4. M4：专家知识库。交付导入、解析状态、卡片、规则审批、运行时专家报告和 evidence bundle。
5. M5：Skill/MCP 扩展。交付导入、扫描、权限、安装、MCP 工具注册和调用审计。
6. M6：生产安全强化。交付密钥隔离、交易所实盘适配、WebSocket 对账、熔断演练和灰度策略。

## 10. 验收标准

1. 创建授权后，Agent 只能在授权范围内生成和执行交易计划。
2. 超范围、无止损、超杠杆、超亏损、授权过期和高风险事件时必须被风控阻断。
3. 每个交易计划必须绑定 analysis_bundle_id、risk_check_id 和 trace_id。
4. 事件卡可持续追加进度并影响交易许可。
5. Cron/At/Every 任务可创建、运行、暂停、恢复、重试并留下日志。
6. 第三方 Skill 安装前必须完成来源、权限、依赖、静态扫描和用户批准。
7. 资料导入后能生成来源元数据、知识卡、交易启发和待审批规则。
8. 审计页可追溯任意交易、任务、事件、Skill 或知识调用。
9. 一键熔断后系统撤销非减风险挂单、禁止新开仓并降级只读。
10. UI 能完整呈现概念图中的驾驶舱布局和主要业务入口。
