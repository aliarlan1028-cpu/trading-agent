# 数字货币合约交易 Agent 专业化整改矩阵

更新日期：2026-07-25

## 结论口径

当前产品定位为“数字货币永续合约交易 Agent 平台 Beta”。只有在 P0/P1 验收全部通过，并积累足够长的前向与小额实盘记录后，才可使用“专业生产级”表述。禁止使用“稳定盈利”“机构级”“无人值守托管大额资金”等未经证据支持的宣传。

## 已落实整改

| 问题 | 风险 | 整改 | 验收 |
|---|---|---|---|
| 匿名 SSE 混入组合/持仓 | 账户数据泄露 | 匿名流只允许市场字段白名单 | 回归测试拒绝 portfolio/positions/未知字段 |
| tenantId 仅存在于认证层 | 跨租户读取交易数据 | V2 分区完成前，公开注册和非 Owner 交易域 fail-closed | 非 Owner 在旧存储上收到 403 |
| 普通交易用户权限过宽 | 可改密钥、插件或直接执行 | 改为最小权限交易员角色 | 不含 admin、MCP/Skill、critical execution |
| 实盘缺少权益/亏损预算仍可警告放行 | 无真实风险基准开仓 | 实盘状态改为硬阻断 | 风控单测覆盖 |
| 默认 smoke 修改生产数据 | 测试污染 | `npm run smoke` 改为只读；完整烟测必须显式运行 `smoke:full` | 默认命令不写业务对象 |
| 重复 clientOrderId 只检查未终态订单 | 重试可能重复下单 | 所有历史状态均作为幂等键，返回原动作 | 终态订单回归测试 |
| 入场没有确认原生止损 | 裸仓风险 | Binance 使用 close-position 条件止损；OKX 使用 attachAlgoOrds；未确认保护则撤入场，撤单失败触发熔断 | 执行状态为 protection_failed，不进入 entry_pending |
| OHLC 同根止盈止损路径过于乐观 | 回测虚高 | 默认按止损先成交 | 回归测试 |
| 前向验证仅 8 笔即可通过 | 统计证据不足 | 默认至少 30 笔、PF≥1.1、90% 单侧期望下界>0；seeded 永不毕业 | 指标中输出标准误和下界 |
| CORS 全开放、缺少基础响应头 | Web 攻击面过大 | Origin allowlist、安全响应头、登录失败限速 | 未授权 Origin 被拒，爆破返回 429 |
| 订单状态只存在内存集合 | 崩溃重试可能重复交易 | SQLite OMS、状态事件、乐观版本、幂等预留与 UNKNOWN 恢复 | 事务、恢复与重放测试通过 |
| 事件发布与订单提交非原子 | 状态已提交但通知丢失 | Transactional Outbox 与定时派发 | OMS 迁移和 Outbox 同事务 |
| 多实例可能同时执行计划 | 重复提交 | SQLite 执行租约与 fencing token | 竞争实例测试通过 |
| 外部知识可携带提示注入 | Agent 被知识源操纵 | 中英文注入检测、知识隔离和 Agent 工具策略 | `npm run eval:agent` |
| 交易所环境硬编码 | 测试可能误连生产 | Binance Testnet/OKX Demo endpoint 与只读契约检查 | 生产环境检查脚本拒绝运行 |
| 主密钥只能来自环境变量 | 密钥轮换与托管困难 | 支持 KMS/Vault sidecar 挂载密钥文件并可强制外部 Provider | 缺失外部密钥时 fail-closed |
| 本地哈希链被误称不可变 | 数据库管理员可重写 | WORM 外送、持久游标、成功 ACK 后推进 | 独立 WORM 端点验收 |
| 前端首包过大 | 首屏与维护性差 | Chat/Pages/Panels/Mobile 动态加载 | 主 JS 约 440KB → 207KB |

## P0：仍需外部环境或较大迁移

### 真正的多租户存储

- 所有交易域表增加不可为空的 `tenant_id`。
- 数据访问必须通过 repository 层自动注入 tenantId，业务代码不得直接访问全局数组。
- `(tenant_id, client_order_id)` 建唯一约束。
- 迁移前保持 `TENANT_ISOLATION_V2` 关闭。
- 需要独立数据库迁移、回滚和越权测试后才能恢复公开注册。

### 持久化 OMS

- OMS、状态事件、Outbox、租约以及核心交易对象已逐实体关系化并按 tenant/resource/id 建索引。
- 状态迁移使用数据库事务、乐观版本号和 outbox。
- 交易所原始事件不可覆盖，支持重放。
- 建立 CREATED → SUBMITTING → ACKNOWLEDGED → PARTIAL → FILLED → PROTECTED → CLOSING → CLOSED 状态机。
- 已接入幂等预留、ACK/拒单/UNKNOWN、部分成交、成交/取消、保护量精度分配和 Outbox；真实交易所行为仍需测试网验收。

### 密钥与不可变审计

- 已支持 KMS/Vault sidecar 挂载密钥文件和强制外部 Provider；实际 KMS 权限与轮换由部署环境完成。
- 已支持按持久游标异步复制到外部 WORM endpoint；实际对象锁由接收端配置。
- 数据库管理员不能同时修改业务数据和外部审计副本。
- 当前 AES-GCM 与本地哈希链适合单机 Beta，不等于不可篡改审计。

### 高可用和灾难恢复

- 已提供 SQLite 执行租约和 fencing token；跨主机集群仍需外部一致性数据库/队列。
- 交易写服务和 Agent 推理服务进程隔离。
- 定期执行断网、交易所超时、部分成交、保护单失败、数据库恢复演练。
- 明确 RPO/RTO，恢复后先只读对账再允许写入。

## P1：核心专业化工作

### 风控

- 保证金率、维持保证金、强平距离与压力价格。
- 日/周/月亏损、连续亏损、策略漂移熔断。
- 滚动相关矩阵、Beta/主成分暴露、净 Delta 和币种簇集中度。
- 盘口容量、预期冲击成本、最大允许滑点。
- 资金费率、基差、未平仓量拥挤风险。
- 数据延迟、交易所错误率和对账异常统一触发只读模式。

### 策略研究

- Purged walk-forward、embargo、参数稳定性热图。
- Bootstrap/Monte Carlo 置信区间和多重检验校正。
- 使用逐笔/更低周期数据解决 bar 内路径问题。
- 手续费档位、真实资金费率、滑点与容量模型。
- 前向模拟与历史预热严格分账。
- 策略组合层回测和资金竞争。

### Agent 评测

- 已建立首批固定离线场景：提示注入、提现、风险绕过和交易来源缺失；仍需扩充数据缺失、极端波动和工具故障集。
- 每个模型、Prompt、工具 schema 和策略版本可追溯。
- Observation、Evidence、Plan、Critic、Risk Review 分层。
- 事实、推断、用户授权和历史经验使用不同的数据类型与可信级别。
- 批准后任何关键输入变化都使批准失效。

### 交易所契约测试

- Binance/OKX 测试网覆盖下单、撤单、改单、部分成交、拒单、双向持仓、逐仓/全仓、精度和限频。
- 测试时间偏差、签名错误、网络重试和响应重复。
- 验证保护单一定为 reduce-only/close-position，且不会反向开仓。

## P2：产品与商业化

- 交易驾驶舱、研究平台、管理/订阅后台拆分路由和权限。
- Chat、Pages、Panels、Mobile 已动态拆包；CSS 仍需按模块拆分。
- 多账户资金分配、策略子账本和智能路由。
- MFA、step-up authentication、双人审批。
- 合规、隐私、风险揭示和用户适当性。
- SLO：行情新鲜度、订单 ACK、保护覆盖、对账延迟、任务成功率。

## 实盘准入门槛

必须同时满足：

1. 所有自动化测试、交易所测试网契约测试通过。
2. 审计链、账户快照、保护单、对账全部健康。
3. 公开注册关闭，或 V2 租户隔离已通过越权审计。
4. API Key 无提现、IP 白名单、KMS 和告警有效。
5. 纯前向验证达到统计门槛；不得用 seeded 记录替代。
6. 初始单笔名义额不超过 50 USDT，并保留人工批准。
7. 连续运行和故障演练达到约定 SLO。
8. 任何一项未知或过期均 fail-closed。
