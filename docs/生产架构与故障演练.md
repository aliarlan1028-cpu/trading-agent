# 生产架构与故障演练

## 支持的租户模式

当前正式支持的模式是“一客户一实例”：独立容器、SQLite 数据卷、密钥、Owner 和子域名。单实例公开注册保持关闭。关系型 `tenant_resources` Repository 与迁移命令已经提供，但在所有业务域完成切换前，`TENANT_ISOLATION_V2` 不得开启。

## 交易执行拓扑

Agent 推理只产生计划；RiskEngine 复查后由 ExecutionEngine 请求交易写网关。网关先取得执行租约，再在 SQLite OMS 预留 `(tenant, exchange, clientOrderId)`，然后调用交易所。ACK/拒单/未知状态/部分成交进入状态事件表，并在同一事务写 Outbox。UNKNOWN 与超时 SUBMITTING 会按 clientOrderId 定时向交易所恢复。保护单没有得到交易所确认时撤销入场；撤销未确认则熔断。

## 密钥

生产设置：

```text
REQUIRE_EXTERNAL_KEY_PROVIDER=true
SECRETS_MASTER_KEY_FILE=/run/secrets/trading-agent-data-key
```

该文件应由 KMS/Vault sidecar 生成并只读挂载，不进入镜像、Git、日志或普通备份。轮换时先停止交易写入，解密旧密钥、重新加密到新密钥，再重启并执行只读同步和审计校验。

## WORM 审计

配置 `WORM_AUDIT_ENDPOINT` 和 `WORM_AUDIT_TOKEN`。接收方必须：

- 位于独立账号或权限域；
- 只允许追加；
- 启用对象锁或合规保留；
- 按 `hash`、`prevHash` 验证链；
- 只有成功返回 2xx 后，本地持久游标才前移。

## 上线顺序

1. `npm test`
2. `npm run eval:agent`
3. `npm run build`
4. `npm run preflight:production`
5. Binance Testnet 或 OKX Demo 下运行 `npm run test:exchange-contract`
6. 只读账户同步
7. 对账和保护覆盖检查
8. 模拟盘纯前向毕业
9. 单笔不超过 50 USDT、人工审批的小额实盘
10. 达到 SLO 后才逐级扩大额度

## 必做故障演练

- 请求超时但交易所实际已接单：相同 clientOrderId 重试必须返回 OMS replay。
- ACK 丢失：订单保持 UNKNOWN，禁止自动再次下单，只允许按 clientOrderId 查询和人工处置。
- 原生止损失败：入场撤销；撤销未确认触发熔断。
- 部分成交：状态进入 PARTIAL，剩余量和保护量必须一致。
- REST 与 WebSocket 不一致：进入只读模式并以 REST 对账结果收敛。
- SQLite/容器重启：Outbox 未发布事件继续派发，OMS 状态不倒退。
- KMS 文件缺失：密钥解密失败，受保护接口锁定，禁止使用开发默认密钥。
- WORM 端点不可用：本地游标不前移并告警，不丢弃审计记录。
- 双实例竞争：只有持有最高 fencing token 的实例允许提交。

## SLO 建议

- 公共行情新鲜度：99.9% 小于 5 秒。
- 私有账户快照：开仓前小于 2 分钟。
- 订单 ACK：P95 小于 2 秒。
- 原生保护覆盖率：100%。
- 对账严重差异恢复：小于 5 分钟。
- 审计 WORM 外送延迟：P95 小于 2 分钟。
