# AI 数字货币交易 Agent 实施路线图

## 阶段 0：需求整合与边界确认

交付物：

1. 统一需求文档。
2. 系统模块地图。
3. P0/P1/P2 范围。
4. 安全边界：真实交易默认关闭、禁止提现、密钥隔离、风控前置。

## 阶段 1：本地可运行 MVP

目标：让系统先跑起来，覆盖概念图和两份 PRD 的核心业务对象。

任务：

1. 创建 React 驾驶舱。
2. 创建 Express API。
3. 创建 JSON 持久化种子数据。
4. 实现授权、风控、交易计划、事件、任务、知识库、Skill、MCP、审计 API。
5. 真实交易写操作默认关闭，执行器只返回受控结果。

验收：

1. `npm run dev` 可启动前后端。
2. 总览页可查看资产、行情、AI 决策、持仓、事件、任务和底部状态。
3. 用户可运行任务、触发风控检查、创建知识分析、扫描 Skill、启用熔断。

## 阶段 2：核心闭环增强

目标：从“静态驾驶舱”升级为“可解释的自主交易流程”。

任务：

1. Mandate 创建、暂停、恢复、撤销。
2. 交易计划编辑、风控检查、执行回执。
3. 事件高风险时自动影响交易许可。
4. 定时任务写入运行日志。
5. analysis_bundle 与交易计划绑定。

验收：

1. 不符合授权或风控条件的交易被拒绝。
2. 通过风控但真实交易开关关闭时，执行器返回“生产写操作被关闭”的受控结果。
3. 所有动作写入审计日志和 trace。

## 阶段 3：专家知识库

目标：让知识库成为交易前置审查能力。

任务：

1. 支持资料来源、权限、版本、状态。
2. 生成书籍卡、概念卡、理论框架、规则草案。
3. 运行时专家分析 API 返回 analysis_bundle_id。
4. 规则审批与风控规则联动。

验收：

1. 每次交易计划生成前可生成 evidence bundle。
2. 专家报告包含核心结论、专家观点、反方观点、规则触发和引用。

## 阶段 4：Skill / Tool / MCP

目标：建立可扩展工具市场雏形。

任务：

1. Skill 来源导入、扫描、权限声明。
2. 安装、启用、禁用和版本 pin。
3. MCP Server 注册、工具列表和权限控制。
4. 调用审计。

验收：

1. 未扫描或未批准 Skill 不能启用。
2. Skill 不能直接获得交易权限。

## 阶段 5：生产化

目标：进入真实交易灰度前的工程化强化。

任务：

1. SQLite/Postgres 持久化。
2. Binance/OKX REST 与 WebSocket 对账。
3. 队列与任务锁。
4. LLM Provider、LangSmith 和成本追踪。
5. 密钥托管、IP 白名单、审计不可变。
6. 异常演练、熔断演练、灰度策略。

验收：

1. 小额度授权灰度。
2. 交易链路 100% trace。
3. 风控拦截 100% 可解释。
4. 任务成功率、对账延迟和异常恢复达到上线标准。
